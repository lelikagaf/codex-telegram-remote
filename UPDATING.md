# Обновление установленного экземпляра

Эта инструкция предназначена для человека или агента Codex, который обновляет
уже настроенный Telegram-пульт.

## Главное правило

Не заменяйте и не публикуйте:

```text
.env
data\state.json
logs\bot.log
```

В `.env` хранится токен Telegram-бота. `data/state.json` содержит выбранный чат,
идентификаторы уже пересланных сообщений и позицию Telegram long polling.

## Обычное обновление Git-репозитория

Остановите бот, получите изменения только с fast-forward и выполните проверки:

```powershell
Stop-ScheduledTask -TaskName "Codex Telegram Remote"
git status --short
git pull --ff-only
npm.cmd test
npm.cmd run check
Start-ScheduledTask -TaskName "Codex Telegram Remote"
```

Если `git status --short` показывает локальные изменения, сначала изучите их.
Не удаляйте их через `reset --hard` и не перезаписывайте пользовательский
`.env`.

Проект не использует сторонние npm-зависимости, поэтому `npm install` обычно не
требуется.

## Обновление копии без Git

Скопируйте из новой версии только:

```text
src\
scripts\
test\
package.json
README.md
UPDATING.md
start-bot.cmd
.env.example
```

Не копируйте `.env`, `data` и `logs`. После копирования выполните тесты и
перезапустите запланированную задачу.

## Что проверить после обновления

1. В Telegram выполнить `/current` и убедиться, что выбран нужный чат.
2. Написать сообщение в этот чат через Codex Desktop.
3. Сообщение с префиксом `💻` должно появиться в Telegram в пределах интервала
   `DESKTOP_SYNC_POLL_SECONDS`, по умолчанию примерно за три секунды.
4. После завершения ответа в Telegram должен прийти отдельный ответ с префиксом
   `🖥`.
5. Несколько уточнений, отправленных во время одного активного хода, должны
   прийти по одному и не дублироваться после перезапуска.
6. Если в Telegram выбран другой чат, ни сообщение, ни ответ пересылаться не
   должны.

## Смысл исправления синхронизации

Ранний вариант обрабатывал только завершённые ходы. Из-за этого сообщение,
введённое в Codex Desktop, появлялось в Telegram лишь после окончания ответа.

Текущая версия:

- опрашивает как активные, так и завершённые ходы;
- сразу пересылает каждый отдельный `userMessage`;
- хранит идентификаторы пересланных сообщений в `data/state.json`;
- продолжает ждать стабилизации финального ответа перед его отправкой;
- мигрирует состояние промежуточной версии, которая запоминала только
  идентификатор хода целиком.
