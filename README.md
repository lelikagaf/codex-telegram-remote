# Telegram-пульт для Codex Desktop

Локальный Telegram-бот для удалённого общения с Codex на Windows-компьютере.
С телефона можно выбирать чаты, отправлять задачи, читать ответы и подтверждать
действия. Бот работает от имени текущего пользователя Windows и использует
авторизацию установленного Codex Desktop.

Проект не является официальным продуктом OpenAI или Telegram.

## Возможности

- `/chats` — последние чаты Codex с кнопками выбора;
- `/current` — текущий выбранный чат;
- `/use N` — выбор чата по номеру;
- `/new Название` — создание нового чата;
- `/sync_topics` — создание Telegram-тем по последним чатам Codex;
- `/model` — просмотр и изменение модели и усилия рассуждений выбранного чата;
- обычное сообщение — новая задача в выбранном чате;
- Telegram-документ — загрузка в `.codex-telegram-uploads` выбранного рабочего
  каталога и передача Codex вместе с подписью пользователя;
- `/status`, `/stop`, `/steer текст` — управление выполняющейся задачей;
- `/approve` и `/deny` — ответы на запросы разрешения Codex;
- потоковое обновление ответа в Telegram;
- финальный ответ на Telegram-задачу отдельным новым сообщением, чтобы телефон
  показывал обычное уведомление;
- автоматическая повторная доставка финала после временного сбоя или
  перезапуска бота;
- немедленная пересылка каждого сообщения, введённого в выбранном чате
  Codex Desktop, не дожидаясь завершения ответа;
- пересылка финальных ответов из Codex Desktop, только если в Telegram выбран
  тот же самый чат;
- отсутствие повторной пересылки задач, запущенных из Telegram;
- автоматическое переподключение после сна и перезапуск при сбое;
- доступ только для одного заданного Telegram user ID.

Если в чате уже выполняется задача, новое обычное сообщение не прерывает её и
не помещается в очередь. Для уточнения используйте `/steer`, для отмены —
`/stop`.

Настройки модели:

```text
/model                              показать текущую модель и доступные усилия
/model list                         показать доступные модели
/model high                         установить усилие для текущей модели
/model gpt-5.6-terra                установить модель
/model gpt-5.6-terra high           установить модель и усилие
```

Списки моделей и поддерживаемых усилий бот получает от текущего Codex
app-server. Изменения применяются к следующим задачам в выбранном чате.

Telegram topics:

```text
/sync_topics      создать темы по 10 последним чатам Codex
/sync_topics 25   создать темы по 25 последним чатам Codex
```

После синхронизации каждое сообщение или документ внутри созданной Telegram-темы
отправляется в связанный Codex-чат. Ответы и файлы Codex возвращаются в ту же
Telegram-тему. В forum supergroup бот должен быть администратором с правом
управлять темами; в личном чате с ботом должен быть включён threaded/topic mode.

## Как это работает

```text
Telegram
   │ HTTPS long polling
   ▼
node.exe — этот бот
   │ JSON-RPC через stdin/stdout
   ▼
codex.exe app-server
   │
   ▼
локальные чаты и рабочие каталоги Codex
```

Входящий сетевой порт не открывается. Telegram и OpenAI доступны только через
исходящие подключения.

## Требования

- Windows 10 или Windows 11;
- установленный и авторизованный Codex Desktop;
- Node.js 20 или новее;
- Telegram-бот, созданный через `@BotFather`;
- интернет-доступ к Telegram и OpenAI.

Сторонних npm-зависимостей нет, поэтому `npm install` не требуется.

## Быстрый запуск

1. Склонируйте репозиторий и откройте PowerShell в его каталоге.
2. Запустите безопасный мастер:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\configure-owner.ps1
   ```

3. Введите токен нового бота в скрытом запросе.
4. Отправьте показанную одноразовую команду `/claim` своему боту.
5. Вернитесь в Telegram и выполните `/start`, затем `/chats`.

Мастер:

- проверит токен через Telegram `getMe`;
- удалит webhook и старые ожидающие обновления;
- определит Telegram ID владельца по одноразовой команде;
- создаст `.env`;
- ограничит доступ к `.env` текущей учётной записью Windows;
- установит скрытый автозапуск через Планировщик заданий;
- запустит бот.

## Ручная настройка

Скопируйте `.env.example` в `.env` и заполните значения:

```dotenv
TELEGRAM_BOT_TOKEN=
TELEGRAM_ALLOWED_USER_ID=
CODEX_DEFAULT_CWD=
CODEX_BINARY=
CODEX_APPROVAL_POLICY=never
CODEX_FULL_ACCESS=false
CODEX_ACTIVE_WRITER_MODE=queue
TELEGRAM_NOTIFY_ON_START=true
TELEGRAM_NOTIFY_AFTER_SLEEP=false
TELEGRAM_MAX_FILE_SIZE_MB=0
RESUME_NOTIFICATION_GAP_SECONDS=120
DESKTOP_SYNC_POLL_SECONDS=3
CODEX_WRITER_IDLE_SECONDS=90
LOG_LEVEL=info
```

Если `CODEX_DEFAULT_CWD` оставить пустым, новые чаты будут создаваться в
`Documents\Codex` текущего пользователя. Если `CODEX_BINARY` пуст, бот
автоматически найдёт актуальный `codex.exe` из Codex Desktop.
`CODEX_FULL_ACCESS=true` включает `never + danger-full-access` для процесса,
старых и новых чатов и каждого хода, запущенного через Telegram. При значении
`false` действует `CODEX_APPROVAL_POLICY`, где доступны `never`, `on-request`
и `untrusted`.
`CODEX_ACTIVE_WRITER_MODE=queue` ждёт, пока Codex Desktop освободит выбранный
чат. Значение `fork` автоматически создаёт продолжение с той же историей и
выполняет Telegram-задачу там, если Desktop удерживает исходный writer.
`TELEGRAM_MAX_FILE_SIZE_MB` задаёт максимальный размер загружаемого документа в
мегабайтах. Значения `0` и `-1` отключают ограничение со стороны бота. При этом
могут сохраняться собственные технические ограничения Telegram Bot API.
`CODEX_WRITER_IDLE_SECONDS` задаёт, через сколько секунд простоя бот закрывает
свой Codex app-server после write-действий, чтобы выбранный чат снова мог
открываться в Codex Desktop без конфликта active writer.

Запуск:

```powershell
.\start-bot.cmd
```

## Проверки

```powershell
npm.cmd test
npm.cmd run check
npm.cmd run diagnose
```

`diagnose` проверяет поиск `codex.exe`, запускает локальный app-server и читает
список чатов без подключения к Telegram.

## Обновление установленного бота

Инструкция для человека или другого агента Codex находится в
[`UPDATING.md`](UPDATING.md). Обновление не должно заменять `.env`,
`data/state.json` и `logs/bot.log`.

## Автозапуск

Установить:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-autostart.ps1
Start-ScheduledTask -TaskName "Codex Telegram Remote"
```

Удалить:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\uninstall-autostart.ps1
```

Задача запускается с обычными правами текущего пользователя, а не от имени
администратора. После сна Windows процесс продолжает работу и переподключается
к Telegram. Когда компьютер выключен, спит или находится в гибернации, бот
недоступен.

## Безопасность

- Никогда не публикуйте заполненный `.env`.
- При утечке токена выполните `/revoke` у `@BotFather`.
- Любой пользователь, кроме `TELEGRAM_ALLOWED_USER_ID`, блокируется.
- `/approve` разрешает действие внутри Codex, но не обходит Windows UAC.
- По умолчанию `CODEX_APPROVAL_POLICY=never` отключает частые запросы
  подтверждения, но не включает опасный обход sandbox.
- `CODEX_FULL_ACCESS=true` дополнительно отключает sandbox и принудительно
  задаёт `approvalPolicy: never` и `sandboxPolicy: dangerFullAccess` для каждого
  задания из Telegram. Используйте только для бота с проверенным владельцем.
- Бот получает доступ к тем же файлам, что и вошедший пользователь Windows.
- Не запускайте весь бот с постоянными правами администратора.
- Не храните рабочий экземпляр на общедоступном сетевом диске.
- Имена документов очищаются от путей и недопустимых для Windows символов;
  неполные загрузки удаляются.

Файлы `.env`, `data/state.json` и `logs/bot.log` исключены через `.gitignore`.

## Ограничения

- Сейчас поддерживается только Windows.
- Чаты и рабочие каталоги читаются из локального профиля Codex текущего
  компьютера. Один OpenAI-аккаунт не гарантирует перенос локальной истории и
  файлов между компьютерами.
- Codex Desktop не всегда обновляет уже открытый интерфейс после хода,
  созданного отдельным app-server. История при этом сохраняется и становится
  видна после обновления интерфейса.
- Используемые методы Codex app-server могут меняться в будущих версиях Codex.
